SECTION 7 — AGENT SPECIFICATIONS (EXACT BEHAVIOR PER AGENT)
================================================================================

ORCHESTRATOR
  - Makes ONE LLM call per turn using instructor + RoutingDecision schema
  - Routing decision logged to routing_decisions list in SharedContext
  - Hard limits: MAXTURNS=10, MAX_TOOL_CALLS_PER_JOB=20
  - Fallback chain (deterministic): decomp → retrieval → critique → synthesis
  - Publishes HANDOFF SSE event with {next_agent, reasoning, confidence}
  - Uses gpt-4o-mini (cost control)

DECOMPOSITION AGENT
  - Produces SubTask list with explicit dependency graph
  - Max 6 sub-tasks (prevent over-decomposition)
  - Each sub-task has TYPE from enum: factual_lookup, reasoning, code_execution,
    data_retrieval, summarization, verification
  - DependencyExecutor runs independent tasks concurrently via asyncio.Event
  - Cycle detection: DFS check on deps BEFORE execution (raises ValueError)
  - Uses gpt-4o-mini

RETRIEVAL AGENT (2-HOP RAG — MINIMUM REQUIRED)
  - HOP 1: embed query → pgvector search → top-5 chunks → partial answer
    Extract SECOND_HOP_QUERY from hop-1 response
  - HOP 2: embed hop-2 query → pgvector search → top-5 new chunks → final answer
  - EVERY sentence MUST be prefixed with CHUNK:{id} or REASONING:
  - parse_provenance() extracts ProvenanceEntry objects from the formatted output
  - Uses gpt-4o-mini for hop-1, gpt-4o for hop-2 synthesis
  - Vector search SQL:
      SELECT id, content, source_url,
             1 - (embedding <=> $1::vector) AS relevance
      FROM document_chunks
      ORDER BY embedding <=> $1::vector
      LIMIT $2

CRITIQUE AGENT
  - Receives ALL prior outputs: subtasks_json, retrieval_answer, draft_answer, chunks
  - Per-SPAN scoring (NOT holistic answer scoring)
  - Flags claim if confidence < 0.6 OR positive contradiction evidence exists
  - flag_reason MUST cite: "contradicts CHUNK:{id} which states..."
  - Only flags with POSITIVE evidence of a problem (not just uncertainty)
  - Uses gpt-4o (quality critical here)

SYNTHESIS AGENT
  - For EACH flagged claim: RESOLVE | REMOVE | HEDGE
  - RESOLVE: rewrite sentence with accurate information
  - REMOVE: if unverifiable and non-essential
  - HEDGE: "may", "some evidence suggests", "researchers disagree"
  - Produces resolution_log: [{original, resolution_type, new_text}]
  - Populates provenance_map with ProvenanceEntry for every sentence
  - Uses gpt-4o

COMPRESSION AGENT
  - LOSSLESS for: JSON, CHUNK:{id}, SRC: annotations, scores, URLs, test case IDs
  - LOSSY (LLM summarizer) for: prose/filler/conversational text
  - Raises CompressionError if structured data ALONE exceeds target_tokens
  - Triggered at 90% budget utilization (FIX-4), NOT at 100%
  - Uses gpt-4o-mini (cost control)

META AGENT
  - Reads eval_results for scores < 0.6 threshold
  - Identifies lowest-scoring (agent_id, dimension) pair
  - Generates PromptRewrite with difflib.ndiff (NOT ndiff — use unified_diff
    for cleaner output, or ndiff for character-level precision)
  - DiffLine schema: {line_type: "ADD"|"REMOVE"|"CONTEXT", content: str}
  - Stores as status=PENDING — NEVER auto-applies
  - Human approval via POST /rewrites/{id}/review triggers targeted re-eval
  - delta_score populated AFTER re-eval run completes

  - For each ProvenanceEntry with source_chunk_id:
    1. Check chunk_id EXISTS in valid_chunk_ids
    2. Check semantic overlap: len(chunk_words ∩ sentence_words) >= 3
  - REASONING: entries always count as valid (agent acknowledged no chunk)
  - score = valid / total (exclude None source_chunk_ids from denominator)

DIMENSION C: Contradiction Resolution
  - flagged = [c for c in claim_scores if c.flagged]
  - For each flagged claim, check if span is REMOVED or HEDGED in final_answer
  - Hedge phrases: ["may", "might", "contested", "uncertain", "some suggest"]
  - resolved++ if span NOT in final_answer OR hedge found nearby (±80 chars)
  - score = resolved / len(flagged)

DIMENSION D: Tool Efficiency
  - actual = context.count_tool_calls()
  - If actual <= expected_max: score = 1.0
  - Else: penalty = (actual - expected_max) / max(expected_max, 1)
         score = max(0.0, 1.0 - penalty)

DIMENSION E: Budget Compliance
  - violations = [v for v in context.violations if v.violation_type == "budget_overflow"]
  - 0 violations → 1.0
  - 1 violation → 0.5
  - 2+ violations → 0.0

DIMENSION F: Critique Agreement Rate
  - Same as Dimension C logic but from Critique's perspective
  - addressed = flagged claims that Synthesis REMOVED or HEDGED
  - score = addressed / len(flagged) if flagged else 1.0

SECTION 13 — KNOWN LIMITATIONS (WRITE THIS HONESTLY IN README)
================================================================================

Be specific. Vague "future work" language is penalised. These exact statements:

1. temperature=0 is not fully deterministic: GPT-4o uses mixture-of-experts
   routing with floating-point non-determinism in distributed inference.
   seed=42 reduces but does not eliminate variance. True reproducibility
   requires model version pinning (e.g., gpt-4o-2024-08-06).

2. seedkb.py uses 30 synthetic documents: Retrieval quality is limited to
   these topics. A production deployment needs a real document corpus via
   web search or document ingestion pipeline.

3. Token-by-token streaming disabled for structured outputs: instructor's
   Pydantic-validated calls cannot stream tokens. TOKEN events are emitted
   only from the synthesis agent's final answer generation.

4. Redis pubsub has no message persistence: If the API pod restarts between
   Celery worker publishing and client SSE listening, events are lost.
   Clients can recover via GET /jobs/{id}/trace.

5. Single-worker EvaluationHarness: Runs 15 cases sequentially (~3-5 min).
   Parallel eval would require an async task pool.

6. pgvector HNSW index rebuild: First query after a cold restart may be slow.
   Run make seed to warm the index before submitting queries.

7. If retrieved_chunks is empty (empty knowledge base), citation_accuracy = 0.0
   for all test cases requiring retrieval. Always run make seed first.
